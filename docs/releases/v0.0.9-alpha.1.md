# v0.0.9-alpha.1

This maintenance release improves recovery and navigation in the learner
workspace following a visual review of the live portal.

- **Recover a reset predicate.** Reset offers **Undo reset** for the exact
  previous body. The recovery belongs to the current exercise and version and
  ends when the learner edits or changes exercises. Saving now distinguishes
  **Saved in this browser** from temporary in-tab storage; **Export progress**
  and **Import progress** describe the portable file actions explicitly.
- **Keep written questions.** Failed or mismatched replies preserve a follow-up
  already typed in the composer. Expired sessions keep the unanswered question
  available for manual recovery. Choosing an AI suggestion and starting a new
  chat no longer discard an unsent question. None of these recovery paths retries
  a provider call automatically.
- **Read earlier conversations.** The small **History** button opens previous
  chats after **New chat**. Up to five chats share a 64 KiB text budget in tab
  memory. Learners can select text or reuse a user question in an empty composer.
  Viewing history makes no provider request. **Continue this chat** selects an
  available earlier conversation for the next explicit send. The backend then
  compresses its retained history into bounded excerpts, preserving roles and
  revision labels, marking the result incomplete, and giving current learner
  context precedence. Browser transcript text is never accepted as history.
  Expired backend history remains readable locally but cannot be resumed.
  Archives clear on reload or an exercise/version/prerequisite context change;
  they are not exported with code progress.
- **Choose a model near the message.** Model and reasoning menus share the input
  frame, with short effort guidance. Explicit choices are remembered as model
  and effort IDs only and validated against the configured catalogue on the next
  load. Removing a model from deployment configuration causes a safe fallback
  to the configured default. Changing selection retains the conversation and
  unsent message without making a provider call.
- **Start with a learning goal.** Immediate starting points help learners
  understand the question, interpret a hint or examine an example. They fill an
  empty composer without submitting it or overwriting existing text. Starting
  points and generated suggestions share the existing three-item limit.
- **Keep feedback in view.** Desktop chat reserves space beside the editor and
  repair-trace column. Narrower non-modal layouts stack the workspace without
  covering feedback. Mobile keeps its keyboard-accessible dialog, and the
  horizontal exercise strip keeps the selected item visible after resizing.

The release also incorporates the temporary Git-fixture cleanup hardening and
bounded CI filesystem diagnostics from `5281664`. Its constructed-race evidence
does not establish the exact OS error of the earlier tagged CI failure.

Canonical remains the default. Existing AST feedback, behavioral scores and
instances, structural locators, private provider configuration, dependent
practices, progress export/import and administration retain their existing
workflows. History compression is deterministic and adds no model call. Resumed conversation
branches keep the same 6,000-byte history boundary for later replies and
recommendations; the original branch stays unchanged. Chat
interactions add no new solver or JVM work.

## Delivery and verification

Deploy matching frontend and backend files from a fresh build and restart the
backend. This release changes the chat service and route handling for explicit
history continuation; updating only static assets is insufficient. IIS uses a
new timestamped package. Preserve private configuration and the exercise
database. Keys and private deployment archives are not public release assets.

The isolated local candidate passed **1,725 Python regressions, 500 engine
checks, 194 portal browser scenarios and 7 dashboard scenarios**, plus the source
release preflight and package validation. Tests include the constructed
large-history continuation case and repeated-reset compatibility. Historical
closure freshness remains explicitly STALE; its reporting gate passes. Hosted
Linux/macOS/Windows and native IIS results are linked from the published release.

A visual agent inspected the real portal at desktop and phone widths. Final
acceptance made three GPT-6 Luna low-effort chat calls and six suggestion
requests, including an explicit compressed-history continuation. It confirmed
draft recovery, local-only history browsing, model selection persistence and
reply visibility after layout changes. Other providers use deterministic adapter
regressions here; this is not an AI-quality comparison. Visual observations
and recovery boundaries are documented in the
[UX review](../ux-v0.0.9-alpha.1.md),
[chat contract](../tutor-chat-spec.md) and
[progress guide](../progress-save.md).

This release does not renew historical Lean certificates or make a new formal
closure claim. Earlier proof and benchmark artifacts retain their original
inputs, source hashes and trust boundaries.
