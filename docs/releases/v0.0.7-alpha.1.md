# v0.0.7-alpha.1

This maintenance prerelease raises model-upload capacity to **100 predicate
groups and 256 solution declarations** and lets administrators choose which
predicates become exercises. It reduces validation overhead while preserving
source, equivalence, authentication and atomic-publication checks.

- **Choose practice predicates.** The backend first parses the original model.
  The administrator selects immutable group names and explicitly validates the
  selection. InvXC alternatives stay together. Unselected predicates and their
  original bodies remain unchanged in the learner's model environment. Discovery
  cannot request Luna suggestions or publish exercises.
- **Constant JVM starts.** Final preparation uses one inspection JVM and one
  sequential, framed validation JVM, regardless of the number selected. The
  preceding discovery uses one inspector, making three sequential starts for
  the complete browser workflow. At most one administrator JVM runs at a time.
  Dependency identity is checked before and after preparation, instead of
  rehashing dependencies for every exercise.
- **Bounded work and retention.** The 60-second preparation deadline and
  256-MiB Java heap remain. Source stays limited to 256 KiB and each body to
  8 KiB. Prepared serialized data is capped at 8 MiB per draft and 32 MiB across
  retained drafts; publication JSON is capped at 2 MiB. These are data and heap
  limits, not a combined service-RSS guarantee.
- **All-or-nothing validation.** Every original InvXC group's alternatives must
  agree under facts-aware, bounded Alloy checks, including unselected groups.
  Every selected solution also receives the existing equivalence checks in its
  retained environment. Malformed source, unsupported dependencies or a failing
  late variant reject the preparation. SQLite publication remains atomic, and
  original source, predicate names and bodies are preserved.
- **Reliable retry and review.** Failed and stale upload drafts are discarded
  without clearing or deleting newer uploads. Only selected exercises receive
  editable metadata. Luna remains optional and can suggest wording only; manual
  review and publication work without a configured provider.

Canonical remains the default. AST feedback, counterexample-safe behavioral
rewards, continuously updated LFU pools, novice guidance, diagrams, source
highlights, candidate review, SQLite and the dashboard remain available.
See the [upload contract](../admin-security-spec.md) and
[administrator guide](../admin-setup.md) for selection and deployment details.

## Validation

The completed local Python run passed 1,423 tests, including 143 targeted upload
and validation regressions. Local checks also passed
21 upload-browser scenarios, 137 main portal-browser scenarios, 500 engine checks
and seven dashboard checks. The upload scenarios
cover 100 groups on desktop and mobile, selected-only publication, 101-group
rejection, oversized escaped metadata, repeated failed validation and retry,
and delayed cleanup preserving a newer upload. Provider paths use mocks or are
disabled; no real OpenAI request is part of this validation.

On the recorded Linux host pinned to two CPU cores, synthetic 100-group final
preparations took 1.074 seconds for standalone predicates, 1.372 seconds for
equivalent variant pairs and 1.726 seconds for byte-distinct, token-identical
pairs. Each started exactly two JVMs; the last case used 200 validation frames.
Maximum individual child RSS was approximately 233–244 MiB. The runs left no
process reservations or owned scratch files. These samples do not establish
arbitrary Alloy solve times or combined service memory. Run
`python scripts/test_upload_capacity.py` to generate fresh evidence.

This release adds no Lean closure claim. Existing proof evidence retains its
own frozen inputs and declared trust boundary; these implementation changes
do not renew historical production bindings.

## Deployment

Build a fresh timestamped IIS ZIP from this version and follow the
[IIS upgrade instructions](../../deploy/iis/README.md). Linux and macOS source
entrypoints remain supported. Cross-platform CI and native IIS acceptance report
their results separately from local synthetic measurements.

Passwords and OpenAI configuration remain private deployment inputs, excluded
from public assets and packages. The private IIS ZIP is not a public release
attachment.
