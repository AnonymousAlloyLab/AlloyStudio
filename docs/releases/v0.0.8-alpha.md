# v0.0.8-alpha

This prerelease grounds AI guidance in the learner's canonical structure and a
small positional CRUD language. Each explanation connects its selected occurrence
and operator to the public exercise question, while concealed repair expressions
remain hidden.

- **Operational repair vocabulary.** ASRL/1 describes CREATE, READ, UPDATE and
  DELETE using `[temporal, quantifier, [inside...]]` addresses and thirteen
  concrete categories. Names and expression payloads are masked. Binding gaps,
  learner insertion anchors and unresolved operations remain distinct.
- **Structural retrieval.** The engine exports the already prepared learner
  representative with exact occurrence addresses and shared-object identifiers.
  The backend retrieves bounded focus, ancestor, child, sibling and binding
  context for each hint. It performs no additional JVM, normalization, solver,
  vector database or embedding-service call.
- **Revision-bound tutoring.** Retrieval uses the exact pinned learner feedback;
  a changed draft or dependency context cannot reuse another pass's evidence.
  Every operation describes the original snapshot, not an invented intermediate
  repair. A matching predicate receives a READ-only overview and encouragement
  to explore other formulations.
- **Bounded optional context.** Export and prompt context have explicit caps.
  Missing, partial or unsupported structure degrades the optional enrichment;
  it does not invent positions or discard otherwise available distance feedback.
  Temporal CREATE remains unresolved when its trace names a target destination.
- **Portable packaging.** IIS and isolated runtime builds include both the DSL
  and retrieval modules. Native portability CI covers the new Python contracts
  and Java exporter self-test.

Canonical remains the default. Raw AST feedback, per-instance explanations,
provider selection, progressive hints, source locators, behavior scoring and
graphics, private administration, candidate review, parameterized/dependent
practices, saved progress and persistent workers retain their existing flows.

## Deployment

Rebuild and restart the backend so persistent workers load the new engine. IIS
deployments require a fresh timestamped package. Keep private provider/admin
configuration and the exercise database. The private IIS archive and credentials
are not public release assets. Linux/macOS use the existing portable entrypoint.

## Verification boundary

The live `gpt-6-luna` check on 2026-10-26 passed all five final scenarios:
multiplicity, binding, temporal, a matching redundant solution and `graphs.inv7`.
It returned all nine operation descriptions, four displayed-instance descriptions
and five summaries with valid IDs. All nine edit units had resolved structural
context. Provider-call times were 2.0–5.8 seconds in this illustrative run; these
five cases are not a quality or latency benchmark. The initial review prompted
an additional instruction to check surrounding guards/exclusions and avoid
treating every supporting edit as a separate semantic defect. See the
[public check summary](v0.0.8-alpha-guidance-check.json).

The isolated ASRL Lean model proves model-level address/role, lookup and
accounting properties without unfinished proofs or new axioms. It is not a
production refinement proof of this Java/Python bridge or an AI nondisclosure
proof. Historical benchmark/proof snapshots retain their original hashes and
are not renewed by this release.
