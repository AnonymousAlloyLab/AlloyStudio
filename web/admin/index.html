Upload format guide

Upload one UTF-8 .als file, up to 256 KiB. Keep signatures, fields, facts and helpers in the same model. All exercise predicates must have no parameters.

  • inv1C0, inv1C1, … are alternative solutions for one inv1 exercise. Capitalization of the base name is preserved. Every variant must agree within the selected Alloy scope.
  • An optional bare inv1 is the learner's starter. Otherwise, a blank practice body is provided. C numbers need not be consecutive; the lowest is the primary behavioral reference.
  • A standalone predicate such as acyclic keeps its name and becomes a single-solution exercise. A file with just one predicate uses the same workflow.
  • Parameterized predicates and functions remain helpers. Do not call private solution variants from another predicate, fact, helper or command. Module macros, duplicate names, recursive exercises and local-file imports are unsupported.

The original upload is retained privately. Solution declarations are removed from the learner view; every retained environment fragment and every solution body is preserved. Luna formats the exercise metadata, not the Alloy code.

Up to eight exercises and 64 solution declarations per file. Each body may use up to 8 KiB. Alloy checks equivalence with facts enforced, bitwidth 5 and the selected scope (1–8); this is bounded agreement, not an unbounded proof.
