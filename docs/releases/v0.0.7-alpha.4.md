# v0.0.7-alpha.4

This prerelease adds private, configurable AI providers while preserving the
existing deterministic live-programming and administrator workflows.

- **Provider choice per role.** Guidance, upload metadata and candidate review
  can independently use OpenAI, Anthropic Claude, Google Gemini, DeepSeek or an
  explicitly configured OpenAI-compatible service. Exact model identifiers and
  reasoning effort are selected in private deployment configuration. The template
  includes Luna, Sol, Astra, Claude Haiku/Opus, Gemini Flash/Argon, and DeepSeek
  Flash. One model is used per request; there are no automatic fallback calls.
- **Portable credentials.** `ai.local.json` and optional private key files stay
  beside the backend, outside `wwwroot`, Git and release packages. Legacy OpenAI
  setup remains compatible. IIS selects the installed private config and discards
  inherited overrides; its existing `-EnableLuna` option enables all AI roles.
- **Same authority boundaries.** Learner guidance retains its redacted evidence
  allowlist and no-solution instructions. Upload suggestions cannot modify Alloy
  source or predicate names. Candidate advice starts only on **Review with AI**,
  cannot admit candidates, and remains subordinate to administrator approval and
  a fresh bounded Alloy check. The perfect-score/no-counterexample admission gate
  is unchanged. UI labels no longer incorrectly attribute every provider to Luna
  or Sol.
- **Bounded adapters.** Provider schemas are translated while local output
  validators remain authoritative. Refusals, tools, malformed or truncated
  responses fail safely. Existing request budgets and concurrency limits remain;
  guidance caches additionally distinguish provider, endpoint, model, effort and
  credential. Nonregular credential files, including FIFOs, are rejected without
  blocking the request.
- **Audited regressions and terminology.** The supplied reward/LFU and ONE-binding
  audit patches add temporal dependency and branch-swap witnesses. The canonical
  caption now explains that identical-looking text can hide declaration-binding
  differences. Evaluation documents and plots use the original arm name HiGenA;
  frozen benchmark evidence and its internal identifiers remain unchanged.

Canonical remains the default. AST hints, progressive explanations, structural
locators, instance graphics, parameterized/dependent practices, saved progress,
100-group uploads, private library management and the CI/CD dashboard remain.
No solver semantics or corpus data are changed by provider selection. This release
makes no new Lean closure claim and does not renew stale production bindings in
historical formal evidence.

## Configuration and deployment

See [AI provider setup](../ai-providers.md), the
[acceptance contract](../ai-providers-spec.md), and the
[IIS upgrade guide](../../deploy/iis/README.md). Provider/model availability was
checked in official documentation; authenticated account access and paid model
calls are not part of the synthetic adapter tests. High reasoning effort can
exceed existing deadlines on some models; deterministic feedback remains usable.

Build a fresh timestamped IIS package and refresh both backend and public files.
Preserve `ai.local.json`, `openai.local.json`, `admin.local.json`, private key files
and the exercise database when upgrading. The private IIS ZIP is not attached to
the public source release. Linux/macOS source deployments use the same config.

## Validation

- Full Python suite: **1,579 tests passed** (517 seconds), including 37 shared
  provider-adapter tests, learner/admin boundaries, corpus checks, candidate
  admission, portable installation and offline proof regressions.
- Complete portal browser suite: **159 scenarios passed**. The Python suite also
  ran the separate administrator and dashboard browser contracts.
- Clean portable build and refreshed timestamped IIS package passed. Native
  Windows/IIS execution is not claimed by the Linux-hosted package tests.
- Delivery checks confirmed empty credential templates, private-config exclusion,
  unchanged corpus/vendor/formal evidence files, and no token-shaped values in
  staged source.

Synthetic provider tests exercised every protocol without using a deployment key
or making paid calls. Official model documentation was checked separately; this
is not an authenticated availability test. Earlier failures in stale provider
fixtures and the local test compiler wrapper were corrected and the complete
suite rerun successfully.
