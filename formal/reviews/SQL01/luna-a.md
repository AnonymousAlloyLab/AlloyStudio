# SQL01 tier 1 adversarial review — Luna A

Verdict: `no_constructed_breach`. I reviewed the frozen SQL01 manifest, both Lean inputs, the theorem inventory, bridge policy and generator, verifier, mutation/browser adapter tests, and the scoped SQL injection note. The manifest SHA-256 is `eff6e64976ce501a133c6c7b15d5848e9cebb5c841da664312f26798270d0998`; all 40 listed input hashes matched. This review is advisory and is not a proof or release-closure decision.

The Lean model makes query syntax come from a registry entry or a fixed control list. Query values are carried separately in `Bound.values`; the execution constructor never derives `Bound.sql` from those values. The separation and trace-closure theorem statements follow that construction. The wire model intentionally starts after JSON parsing; its round-trip results do not prove JSON parser correctness. The inventory records empty axiom lists, and `Audit.lean` rejects project axioms and theorem dependencies, including standard axioms. I inspected the proof sources and inventory but did not run Lean in this review.

The bridge binds its generated registry and controls to the checked compiled artifact bytes, checks the production executor and parameter adapter bodies against restricted expected ASTs, and accounts for the row adapters, SQLite execution sinks, fixed controls, and schema statements. The internal table helper call sites are constrained to literal table names. Unrecognized local imports and database execution shapes fail closed. The mutation suite includes direct interpolation, escaped/reflected execute capabilities, request-selected table access, source import expansion, artifact substitution, and registry rebinding. The browser adapter test executes the current admin API source with SQL-shaped JSON values and checks the serialized request body; I inspected these tests but did not execute them.

The registered construction covers SQL code/data separation for arbitrary modeled backend values and checked correspondence to the frozen restricted source shape. The declared trust remains material: Python/JavaScript/JSON behavior, the extractor and integrity routines, Lean distribution/kernel, SQLite binding, hashes, OS and hardware. This does not establish complete JSON correctness, the full application authorization model, SQLite semantics, future source integrity, or universal portal immunity. These are explicit trust boundaries or exclusions, not constructed counterexamples to the registered claims. No frozen input was edited; no credentials or restricted configuration were read; no network or toolchain installation was used.
