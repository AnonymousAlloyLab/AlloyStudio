# v0.0.9-alpha

This prerelease adds a foldable **Ask a tutor** panel that keeps a conversation
while the learner edits a predicate or changes tutoring models. Each new turn
uses the current question and learner context; it does not require a new chat
session after each edit.

- **Contextual conversation.** The tutor can read the public exercise prompt,
  current learner code, nearest-distance edit trace, positional CRUD operations,
  learner structural context and up to twelve displayed behavioral instances.
  It reuses exact pinned feedback and never starts another JVM or solver. An
  incomplete draft can be discussed without compiled evidence; absent evidence
  is identified explicitly.
- **Live context changes.** Code edits and metric changes retain the discussion
  and mark older replies as belonging to an earlier draft. Current evidence is
  checked against the body, revision, exercise and dependency context. Late
  responses cannot replace the current draft's feedback. Changing exercise or
  prerequisite context starts a separate conversation.
- **Model changes within a conversation.** Configured OpenAI accounts offer
  GPT-6 Luna, GPT-6.1 Terra and GPT-6.1 Sol with supported reasoning settings;
  Claude accounts offer Haiku, Sonnet and Opus 5.5; Gemini accounts offer 3.8
  Flash and 4 Argon. Changing model, provider or effort preserves history and
  the unsent message. The next explicit send uses that selection, and replies
  identify their model and effort. Model availability still depends on the
  deployment's provider account.
- **Suggested questions.** At most three clickable suggestions use the selected
  provider's inexpensive model: Luna, Haiku or Flash. Opening the panel,
  refreshing suggestions or finishing a turn can request them. Typing and
  changing model selections make no provider calls. Switching providers also
  switches the provider that receives the retained learner conversation on the
  next explicit send.
- **Private configuration and bounded work.** Keys remain in backend deployment
  configuration. The browser cannot supply keys, provider URLs, arbitrary models
  or fabricated conversation history. Chat shares the existing two-call AI
  capacity, admits one active call per learner channel and has no waiting queue.
  Bounded memory retains the last six exchanges; conversation tokens expire
  after thirty minutes. History is temporary and is not saved across page
  reloads or server restarts.
- **Portable delivery.** Linux, macOS, Windows and IIS inventories include the
  chat service, model catalogue and public UI module. The panel supports
  keyboard navigation and a mobile overlay. The hosted-runner regression for
  cold-worker startup now uses deterministic timing coordination.

Canonical remains the default. Raw AST feedback, progressive edit hints,
per-instance explanations, behavioral scores and diagrams, private
administration, candidate review, dependent practices, saved progress and
persistent analysis workers retain their existing flows.

## Deployment

Rebuild and restart the backend, and deploy the matching frontend assets. IIS
requires a fresh timestamped package. Keep private provider/admin configuration
and the exercise database; neither credentials nor the private IIS archive are
public release assets. Linux/macOS continue to use the portable entrypoint.

Without an explicit `chat` configuration, only the existing guidance provider's
stack is enabled. Administrators can authorize multiple providers through the
private `chat` profile mapping or disable the panel's service. Upload and
candidate-review credentials are not implicitly reused. See
[provider configuration](../ai-providers.md#learner-chatbot-model-selection).
Unavailable account/model combinations return a bounded error rather than
silently switching provider.

## Verification boundary

The regression suites cover context and history ownership, continuity across
edits and model changes, exact evidence pins, stale response suppression,
provider schemas, response limits, account/cache isolation, shared concurrency,
keyboard/mobile interaction, literal text rendering, and package inventories.
Release CI reports its platform results separately.

A live GPT-6 Luna check on `graphs-inv1` continued one conversation across a
learner edit: the second turn received revision 2 and the new distance of 3,
rather than the previous distance of 8. It discussed the revised expression and
acknowledged that behavioral evidence was absent for that request. Live
suggested questions and a rendered reply were also checked. Claude and Gemini
adapters were exercised with synthetic provider responses, not live accounts.
These checks demonstrate specific behavior, not an AI quality benchmark.

The tutor prompt requests novice-friendly guidance instead of a complete answer.
Hidden oracle bodies and correct-pool expressions are excluded from its context;
prompting and output validation do not prove that an external model can never
infer an answer. Bounded behavior checks are not presented as unbounded proofs.

The named route-service registry records the new chat capability while preserving
the registered HTTP Handler fingerprints. This is a reviewed structural update,
not renewed Lean closure. Historical benchmark and formal evidence retain their
original source hashes and claims.

See the [chat contract, limits and verification details](../tutor-chat-spec.md).

## Post-release CI maintenance

The tag-triggered Linux run failed one of 1,711 Python tests while deleting the
fresh-clone witness's temporary source repository, before setup or engine
execution. The release commit's preceding branch CI and local suite had passed.
The original report recorded the deletion line but omitted the OS error, so the
specific filesystem failure cannot be recovered from that report.

The follow-up test harness disables automatic Git maintenance in the disposable
repository and tolerates only already-removed descendants during cleanup,
matching newer Python's behavior. A constructed deletion race failed the old
cleanup and passes the new one; missing roots, permission errors, I/O errors,
nonempty directories and incomplete removal still fail. CI now reports fixed
filesystem-error categories without exception text, filenames or model data.
This maintenance change does not change the portal runtime, its deadlines or
the published `v0.0.9-alpha` tag.
