# v0.0.7-alpha.5

This prerelease fixes Canonical feedback for SmartContract's Sending Ether
practice and extends recognition of Alloy's bundled utility-library calls.

- **Complete declaration inventory.** The finite callable ledger now records all
  **175 public signatures** in the bundled utility sources, compared with 20 in
  alpha.4. This covers integer arithmetic and comparisons, Boolean operators,
  graph properties, relation helpers, natural numbers, ordering, sequences and
  ternary relations. Names, kinds and arities are checked independently against
  the bundled parser declarations.
- **Executable library coverage.** Typed symbolic calls exercise **150 signatures
  on Linux/macOS and 138 on Windows**. Legacy `util/sequence` has three pre-existing
  type errors and blocks its 25 signatures everywhere. On Windows, `util/natural`
  also hits a bundled parser import-alias collision and blocks its 12 signatures
  before Canonical. These are explicit tested boundaries; the JAR stays unchanged.
  Ordinary `seq`, `util/seqrel` and parser-expanded `util/time` macros work.
- **Windows import metadata.** Alloy's implicit integer import can arrive as
  `util\integer`; the adapter normalizes module filenames to `/` for lookup and
  identity while preserving actual aliases and call targets. This fixes Sending
  Ether on Windows as well as Linux/macOS.
- **Authenticated imports.** Direct, aliased, implicit sequence and public nested
  imports retain parser declaration authority. Nested parameterized imports keep
  their parent instantiation identity. Unknown declarations, fabricated references,
  and invalid kinds/arities remain rejected. Calls remain opaque and arguments
  ordered; there are no new arithmetic or library-body rewrite rules.
- **Sending Ether repair.** Built-in `plus` and `minus` no longer cause
  `UNSUPPORTED_FORM`. The parameterized temporal practice and its dependent
  `deposit` work in Canonical and AST modes. A changed transfer guard produces a
  located repair operation, and a bounded Alloy witness confirms the difference.

Canonical remains the default. AST hints, AI-provider selection, progressive
explanations, source locators, instance graphics, parameterized/dependent practices,
saved progress, private administration, candidate review, 100-group uploads and
persistent JVM workers are preserved. No corpus or bundled dependency bytes change.
Historical benchmark/proof artifacts keep their hashes; this release does not
renew stale formal production bindings.

## Deployment

Rebuild and restart the backend so persistent workers and caches load the new
engine. The uploaded SmartContract does not need rewriting or re-importing.
For IIS, create and deploy a fresh timestamped package through the
[IIS upgrade workflow](../../deploy/iis/README.md), updating backend and public
files. Preserve private provider/admin configuration and the exercise database.
The private IIS ZIP and access tokens are not attached to the public release.
Linux and macOS use the same engine through the portable build entrypoint.

See the [complete library inventory and limitation](../alloy-library-callables.md)
and the [Sending Ether diagnosis](../smart-contract-canonical-feedback.md).

## Validation

- The **1,594-test Python suite passed** before the Windows metadata refinement,
  covering learner/admin/provider, persistence, portability, corpus and formal
  regressions. After refinement, **23 targeted tests passed**, including the two
  added platform tests; release-tag CI reruns the complete suite.
- **500 engine self-checks passed** after a fresh portable build and timestamped
  IIS package validation.
- **159 portal browser scenarios** and **7 dashboard checks** passed.
- Library harness on Linux/macOS: **175 independently parsed signatures**, **150 zero-distance
  comparisons**, **150 positive mutation comparisons**, **150 opaque CALL witnesses**,
  **525 invalid-signature rejections** and **12 forged nested/private-call rejections**.
  Nested aliases, distinct module instantiations, implicit sequences, time macros
  and recovery after parser-invalid input are covered. Windows explicitly asserts
  138 executable signatures and the additional 12 parser-invalid natural declarations.
- Existing framework suites: **4,487 authority checks** (including 441 rejection
  controls), **161 extraction checks** and **45 non-temporal corpus checks** passed.
- Real SmartContract HTTP feedback: four successful requests across Canonical/AST,
  identity/strict-guard cases, exact source ranges and **one reused feedback JVM**.
- Independent source/inventory and resolver reviews found no concrete new defect.
  Historical source-freshness record integrity passes; AP01, TRF-00 and TRF-01
  production bindings remain explicitly `STALE`.

The library tests use one 256-MiB, two-CPU JVM, keep scratch under `build/`, and
make no AI-provider calls. Windows and macOS CI include both the new library and
Sending Ether suites. Linux-hosted packaging checks do not substitute for the
separate native Windows/IIS acceptance workflow.
