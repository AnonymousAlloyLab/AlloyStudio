# v0.0.7-alpha.3

This maintenance prerelease adds dependent practices and portable learner
progress while retaining the existing live programming features.

- **Dependent practices.** New uploads derive an acyclic graph from actual Alloy
  calls, including calls through retained helpers. Numbered solution aliases get
  typed forwarding wrappers when needed. Cycles and dependencies from facts or
  declaration domains remain rejected. Downstream questions show their required
  predicates and stay locked until those implementations are verified.
- **Verified learner environments.** Structural distance must be exactly zero,
  and completed behavioral checks must score exactly 1.000 without
  counterexamples. Opaque backend receipts bind the exact code, exercise version
  and prerequisite context. Both student and reference models use the same last
  verified learner prerequisite bodies. Blank downstream slots cannot be called
  to bypass the checks. Locked requests and receipt inspection start no JVMs.
- **Save progress.** Save and Load move drafts, last verified implementations,
  bounded history, badges and preferences in a portable JSON file. Import is
  validated before its single storage commit and starts no analysis or AI calls.
  Restore checks revalidates saved implementations sequentially, in prerequisite
  order, with cancellation and no Luna calls. Changing verified prerequisite
  code invalidates dependent checks.
- **Private administration.** Original uploads and unselected declarations stay
  unchanged. Publication and candidate approval validate against the author's
  correct prerequisite environment. Candidate observations retain their learner
  context identity. Removing an active prerequisite with dependents is refused.

Canonical remains the default. AST hints, progressive guidance, source
highlights, instance diagrams, parameterized headers, candidate review,
administration and the CI/CD dashboard remain available. The 100-group and
256-solution upload limits, two sequential preparation JVMs, 60-second deadline,
bounded worker lanes and 16-KiB learner ingress limit remain in force. Existing
version-one and version-two upload archives retain their verification rules;
new uploads use version-three source witnesses and bound certificates.

Completion receipts are process-local, limited to 1,024 entries and 8 MiB, with
a 24-hour absolute expiry. After restart, eviction or deployment transfer, saved
code remains available but must be rechecked. Progress files are limited to
4 MiB, 200 exercises, 8 KiB per body and 12 history entries per distance mode.
These are bounded checks, not unbounded equivalence proofs. This release adds
no Lean closure claim and does not renew historical production correspondence.

See the [acceptance contract](../practice-dependencies-progress-spec.md),
[learner progress guide](../progress-save.md) and
[administrator guide](../admin-setup.md).

## Deployment

Build a fresh timestamped IIS ZIP and refresh both backend and public assets
using the [IIS upgrade guide](../../deploy/iis/README.md). Backend restarts require
learners to use Restore checks. Linux and macOS source entrypoints remain
supported. Administrator passwords and OpenAI keys remain deployment-local;
the private IIS archive is not a public release attachment.

## Validation and boundaries

Six real Alloy integration scenarios passed, including typed `InvXC` aliases,
helper transitivity, private candidate approval, a 100-practice dependency chain,
and a real HTTP A-to-B-to-C completion workflow. Locked requests, catalogue visits
and progress inspection launched no workers. Completed edits and distinct saved
contexts reused the same two persistent worker PIDs. The guard harness passed
195 constructed assertions in a single JVM. Independent authority review passed
20 pure and fake-HTTP tests; the progress browser harness passed 21 scenarios,
including storage failure, malformed imports, expiry, restoration and mobile UI.

The supplied private SmartContract model successfully prepared and published
`sendEther` and dependent `deposit`. AST reported distance zero for the exact
dependent body. Canonical retained its existing arithmetic normalization boundary
and returned `UNSUPPORTED_FORM`, with no distance or false completion. This
release does not claim to extend the normalizer. Source clones execute a portable
representative with the same parameter interfaces; they do not require the private
SmartContract file.
