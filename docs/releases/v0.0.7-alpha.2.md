# v0.0.7-alpha.2

This maintenance prerelease fixes uploads whose retained aggregate predicates
refer to selected practices and adds explicitly parameterized practice predicates.

- **Recoverable selection.** No predicates are selected automatically. Control
  and transaction helpers can stay in the environment. Failed validation discards
  the rejected backend draft while preserving the local file and choices for a
  changed selection and fresh validation. Logout, file changes and explicit
  discard clear that local state; it cannot request AI or publish by itself.
- **Aggregate callers.** Unselected helpers, assertions and commands remain
  unchanged. Other selected standalone answers become named blank TODO slots in
  each exercise so aggregate callers still compile without showing those answers.
  Numbered C aliases remain hidden. Answer-to-answer calls, recursion and facts
  depending on practices remain rejected. Dependency errors identify the caller
  and hidden predicate. Existing version-one source witnesses remain verifiable
  with their original projection.
- **Typed practice headers.** Predicates such as `pred reachable[n: Node]` retain
  their names and explicit parameter declarations above the editable body.
  Numbered variants and a bare starter require matching argument interfaces.
  Up to 16 argument names, relation arity eight and an 8-KiB header are supported;
  grouped/disjoint, dependent, set-valued and relation-valued declarations are
  checked, including exact-bound aliases such as `n = Node`. Receiver-style
  predicates remain helpers; use explicit arguments for a practice. Functions
  remain helpers. Both Canonical and raw AST hints compare the editable body.
- **Argument-aware checking.** Bounded equivalence searches for disagreement at
  the same legal argument assignment. Behavioral score samples and LFU identities
  include that assignment, and each diagram shows its parameter values. No atoms
  or model relations are added. Undercoverage or overcoverage still prevents a
  score of 1.000. Luna receives only the projected student argument values with
  its existing novice guidance evidence; provider calls are optional.
  Parameterized temporal enumeration uses exact trace lengths within the existing
  1..10 bounds to preserve argument bindings when traces grow.

The 100-group/256-solution upload bounds, two sequential JVMs per final
preparation, 60-second deadline, 256-MiB heap, SQLite atomic publication and private
configuration remain. Canonical remains the default; AST, highlights, progressive
hints, diagrams, candidate review and the dashboard remain available.

See the [upload contract](../admin-security-spec.md) and
[administrator guide](../admin-setup.md). Cross-platform and native IIS checks
are recorded separately from local validation. This release adds no Lean closure
claim and does not renew historical production correspondence.

## Validation

The completed local Python run passed **1,489 tests**, including the 24-scenario
offline administration browser harness, 39 behavioral-engine tests and 37
private-validator tests. The main portal passed 138 browser checks. Engine
self-tests passed 500 checks and the dashboard passed seven browser checks.
Provider paths use mocks or are disabled; no paid
OpenAI requests are part of validation.

The supplied SmartContract model prepared 17 selected practices, including
`onlyOwner[s: Address]`, in 3.380 seconds under the final engine. Its inspector
and 17-frame validator batch ran sequentially. Isolated SQLite publication/reload
passed; every unselected declaration remained byte-for-byte unchanged, selected
answer declarations stayed out of public environments, and the private source
stayed intact.

On the recorded Linux host pinned to two CPU cores, 100-practice preparations
took 1.269 seconds for standalone predicates, 1.480 seconds for parameterized
predicates, 1.261 seconds for equivalent variant pairs and 1.659 seconds for
byte-distinct, token-identical pairs. Each started exactly two JVMs, with a
live-process high-water mark of one; the last used 200 validation frames.
Maximum individual child RSS was approximately 235–241 MiB. No process
reservations or owned scratch files remained. These are synthetic measurements,
not arbitrary solve-time or combined service-memory guarantees. Run
`python scripts/test_upload_capacity.py` for fresh receipts.

The [frozen reward/LFU replay](../../scripts/replay_reward_contract.py) passed
two identical offline kernel builds with 92 declarations, an empty axiom audit,
eight model claims, four witnesses and all four negative controls. Its 14
boundary tests passed. The outer result is `REPLAY_PASS` for historical inputs;
it leaves the current production binding `NOT_ESTABLISHED` and does not rewrite
the old evidence. Current-source freshness continues to report the existing
TRF-00, TRF-01 and AP01 bindings as `STALE`.

## Deployment

Build and extract a fresh timestamped IIS ZIP, then follow the
[IIS upgrade instructions](../../deploy/iis/README.md) to refresh both public
assets and the backend. The private ZIP is not a public release attachment.
Linux and macOS source entrypoints remain supported. Administrator passwords and
OpenAI keys remain deployment-local configuration, outside public assets and Git.
