# Windows admission-refusal regression evidence

This immutable archive preserves a native Windows transport failure, the
existing admission contract, and a test-only correction with constructed local
evidence. It does not establish closure, reviewer approval, deployment
correctness, a Windows rerun pass, or a universal transport guarantee.

Windows job `111517882855` in run `37230133497`, at commit
`b35aa68d31167e7311635cca75a62dda1c6be78f`, failed the native HTTP regression
step. The raw job log records 110 tests with one error:
`test_enabled_pair_actual_saturation_control_health_and_limits` expected a
received 503 response, but `HTTPConnection.getresponse()` raised
`ConnectionAbortedError: [WinError 10053]`. The saved overall-run snapshot was
still in progress; the Windows job itself was complete.

Earlier Windows job `111513106171`, run `37228525806`, at commit
`ad6ea7ccc40f04d8022063fcf6012e6aef7fb3da`, passed its native checks. The two
commits' admission-test files are byte-identical. This establishes neither a
failure rate nor the precise cause of the later peer abort. The earlier overall
run failed its separate Linux Python step, so its native pass is not presented
as a complete CI pass.

The preexisting contract requires a bounded constant refusal attempt followed
by close, without allocating a request thread or parser. It does not require
successful response delivery. The preserved context test already treats only
specific peer-close outcomes as admissible while checking the real admission
decision and counters. The correction applies that distinction to the newer
admission test; it does not change the production refusal implementation or
the existing contract.

`ci/` contains exact original logs and CI metadata. `before/` contains the test
bytes retrieved from each exact commit. `contract/` and `context/` preserve the
existing contract and earlier refusal-test pattern. `after/` and `local/`
contain the corrected test and the separately documented local evidence.
All original records and older verification/review archives remain unchanged.
Private configuration and deployment artifacts are excluded.

The corrected source accepts only connection reset, connection abort, and broken
pipe at the refusal boundary. It still checks the real reserve decision, exact
rejection increment, unchanged acceptance/peak counts, and precise status,
Retry-After, and retryable JSON whenever a response is delivered. Successful
health and route assertions remain strict. The focused socket suite passed
14 tests.

The local injected witness runs real paired listeners, receives each server
response, then injects a client-side `ConnectionAbortedError(10053)` for refusal
responses. The before test fails and the after test passes. A separate injected
nonblocking-send failure directly exercises production `process_request`:
one bounded send attempt, shutdown, close, one rejection, and no new request
thread. Ten controls cover valid delivery and the three accepted peer-close
errors, while rejecting wrong admission decisions, wrong response details,
timeouts, and unrelated OS errors. These are explicit injections, not a native
Windows reproduction.

`native-linux-schedule-witness.json` separately preserves observations of normal
ordering and server-close-before-client-send ordering. Both delivered 503 on
Linux. That historical observation is not generated by `verify_refusal.py` and
does not reproduce WinError 10053.
