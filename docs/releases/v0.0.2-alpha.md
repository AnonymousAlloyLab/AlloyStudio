# v0.0.2-alpha

This release adds constructive Lean proofs for SQL code/data separation and
checked mappings to Alloy Studio's production SQLite adapter and request paths.
Untrusted values remain bound parameters; they cannot alter the SQL bytes of a
selected registered operation. Arbitrary request values are covered by the
model, without relying on browser validation.

The standalone offline verifier requires two clean, deterministic proof builds,
zero axiom dependencies, complete theorem/source inventories, and an ordered
review ladder of two GPT-6 Luna, two GPT-6 Sol, and two GPT-6 Astra reviewers.
The generic proofs are instantiated with the actual query registry. Executable
tests additionally cover injection payloads in every text parameter, real
authenticated Alloy uploads, publication, reload, backup, browser JSON
serialization, and deliberately broken source-mapping cases.

The claim is SQL separation under explicit trust in the source extractor,
Python/JavaScript and JSON semantics, SQLite binding, Lean kernel/toolchain,
hashing and host. It is not universal application immunity or a completion of
the original 24 whole-portal proof obligations. See the
[precise proof boundary](../sql-injection-proof.md).

This release also includes the macOS temporary-path packaging fix, timestamped
private IIS builds, SQLite exercise storage, authenticated model uploads and
SQLeanParser attribution added since the initial alpha. Administration is
configured separately on each deployment; source releases contain no configured
password or OpenAI key. Private IIS archives are built locally and are not
public release assets.
